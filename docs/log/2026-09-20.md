## Audio — footsteps
- `src/audio/AudioManager.ts`: single WebAudio bus; synthesized footstep
  (filtered noise burst + envelope, randomized). Context resumes on first user
  gesture. `Player.onFootstep` fires once per PI of walk phase (per step, grounded
  only). Verified: 4 steps over 1.5 s walking; context state `running`.
- Foundation for later city ambience, birds, traffic, environmental loops (§57).

## Day/night cycle
- `src/world/TimeOfDay.ts`: one hour value drives sun direction, sky/fog color and
  light intensity; hold **T** to fast-forward (default 480 s/day).
- `Lighting.applyTimeOfDay` + `SceneManager.setSky`; HUD clock.
- Night gets a cool moon key light + ambient floor so it stays navigable;
  twilight uses smoothstep. Verified morning/noon/sunset/night screenshots.

## Device geolocation
- `src/geography/Geolocation.ts` (getCurrentLocation / watchLocation /
  insideWorldBounds). The game now **spawns at the device's real location** when
  inside the world bounds, else falls back to the configured spawn.
- **L** recenters on the device, **G** toggles live tracking; HUD `GPS lat, lon`
  line and a green minimap marker.
- Verified with a mocked position (22.3475, 91.8362): player spawned there and
  the HUD/minimap matched.

## Minimap + named-place identifiers
- `src/ui/Minimap.ts`: Canvas2D minimap bottom-right (§55, MVP-core). Reuses the
  same world vectors as the scene — static world rendered once to an offscreen
  canvas, then a player-centred crop blitted each frame with named-place labels,
  a facing arrow and a compass. Toggle with **M**.
- Requires the world data to be reusable: `Roads.roads` and `Buildings.list`
  are now exposed.

## Vehicles
- `src/vehicles/Vehicle.ts` + `VehicleManager.ts`: simple procedural car and
  bicycle. **C** summon car, **B** summon bicycle, **F** mount/dismount.
  Arcade W/S/A/D, terrain-following, wheel spin.
- Fixed two bugs: controls were reversed (heading was stale on mount — now
  heading = camera yaw + π and the camera trails the vehicle), and the avatar
  vanished while riding (now kept visible and seated via `syncRider`).
- Verified: W displaces the vehicle along camera-forward; 60 FPS.

## Riding pose fix
- Added `PlayerAvatar.animateRiding(phase)`: seated pose — torso leans forward,
  arms reach the bars, legs extend forward and pedal. Implemented for both the
  Blender GLB and the procedural fallback; `animate()` resets `upper.rotation.x`.
- `VehicleManager.syncRider` now seats the hips (avatar hip is 0.92 up from its
  feet origin): car hip 0.55, bicycle hip 0.86, rider shifted 0.32 back onto the
  saddle. `Player.updateRiding` drives the pedal phase while mounted.

## Vehicle camera + bike orientation fixes
- Camera is now **free to orbit while riding** (mouse drag / wheel zoom), same as
  on foot; it only follows the vehicle position. Removed the forced
  `yaw = heading + π` lock.
- Fixed the bicycle geometry: the handlebar had been built on the same side as
  the saddle, so the rider looked like they faced backwards. Rebuilt the frame
  with the handlebar/fork at +Z (front) and the saddle at -Z (rear). Verified
  from a side view: rider faces the direction of travel.
